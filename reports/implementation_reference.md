# Civil Comments toxicity classification

A reproducible BERT-family experiment comparing a frozen feature extractor, end-to-end fine-tuning, and hyperparameter-tuned fine-tuning. It also prepares sourced real-world examples and LIME explanations.

**Execution status:** the full dataset audit and a tokenizer-only length analysis have been run on the downloaded Parquet files in this directory. Training, hyperparameter search, model evaluation, and LIME have deliberately **not** been run, following the request to limit execution to dataset understanding. Model metrics and explanations will be generated by the commands below; no model-performance numbers are fabricated. Python syntax and JSON files were statically checked; training and LIME paths have not been runtime-validated. Only the existing UV environment is used.

## Dataset findings

The target is **`label = int(toxicity >= 0.5)`**: 1 = toxic, 0 = not toxic. A score exactly equal to 0.5 is toxic. The score summarizes human judgments; converting it to a binary label discards disagreement information. This annotation threshold is fixed throughout the experiment and differs from a model's prediction threshold.

All **1,999,514** rows were audited, including every score column. See [the observed audit](reports/dataset_analysis.md), [machine-readable statistics](reports/dataset_audit.json), and [distribution plots](reports/dataset_distributions.png).

| Official split | Rows | Not toxic | Toxic | Toxic rate | Median words | P95 words |
|---|---:|---:|---:|---:|---:|---:|
| Train | 1,804,874 | 1,660,540 | 144,334 | 7.997% | 35 | 159 |
| Validation | 97,320 | 89,649 | 7,671 | 7.882% | 35 | 159 |
| Test | 97,320 | 89,543 | 7,777 | 7.991% | 35 | 159 |

There are no nulls, blank comments, non-finite scores, or scores outside [0, 1] in these files. The schema is `text` plus seven floating-point annotation columns. Only `text` is a model input; auxiliary annotation scores are never features.

The class proportions and length quantiles are similar across the splits. This supports retaining the official split structure, but does not prove absence of domain or demographic shift. Author IDs, timestamps, and identity-membership labels are absent from this configuration, so author-level leakage, temporal drift, and demographic fairness cannot be established from these columns. `identity_attack` is an annotation score, not an identity-membership field.

An always-not-toxic rule achieves approximately **92% accuracy**. Consequently accuracy alone is unsuitable for model selection. **Average precision (AP)** is the primary selection metric, with toxic-class precision, recall, F1, macro F1, balanced accuracy, ROC-AUC, and confusion matrices reported alongside it. AP is the non-interpolated precision–recall summary implemented by scikit-learn; it is not labeled as trapezoidal PR-AUC.

### Duplicates and label ambiguity

| Check | Train | Validation | Test |
|---|---:|---:|---:|
| Exact duplicate rows beyond first occurrences | 24,051 | 474 | 458 |
| Normalized duplicate rows beyond first occurrences | 28,366 | 565 | 573 |
| Normalized groups containing both binary labels | 809 | 26 | 21 |
| Scores exactly 0.5 | 37,896 | 2,022 | 1,989 |
| Scores in [0.4, 0.6] | 129,241 | 6,831 | 6,898 |

There are **1,320** shared normalized texts between train and validation, **1,363** between train and test, and **686** between validation and test. These counts are unique texts, not row counts. Normalization uses Unicode NFKC, case folding, and collapsed whitespace, followed by a 128-bit BLAKE2b hash. Original text is retained for tokenization. This catches exact and formatting repeats, not paraphrases or all near duplicates.

Before sampling, the pipeline removes within-split repeats and shared normalized texts with priority **test > validation > train**. Within each split, the first original row is retained, including its original label. Conflicting labels are reported rather than resolved by using annotations from another split. This leaves 1,774,208 train rows, 96,069 validation rows, and 96,747 test rows. The resulting test set is a deduplicated subset, so its results are not directly comparable to a full official leaderboard score.

The audit also records positive counts at label thresholds 0.4 and 0.6. They demonstrate sensitivity to the task definition; the experiment continues to use the predeclared 0.5 threshold. Ambiguous comments remain in the data.

## Experiment design

The model is [`distilbert/distilbert-base-uncased`](https://huggingface.co/distilbert/distilbert-base-uncased), a six-layer model distilled from BERT. It offers a practical size for this assignment and local Apple Silicon compute. It is a general pretrained language model, rather than a pretrained toxicity classifier that might already have seen Civil Comments labels. The resolved checkpoint revision and package versions are recorded when training starts.

All runs use the same encoder architecture, attention-mask-aware mean pooling, and a dropout-plus-linear two-class head. The original punctuation, profanity, negation, and identity terms are retained. The tokenizer performs its pretrained uncased processing. Stopword removal, stemming, and profanity removal would discard useful context.

The maximum sequence length is **256 WordPiece tokens**, including special tokens. Whitespace-word counts are not token counts. The completed [tokenizer-only audit](reports/tokenizer_analysis.md) used 5,000 stratified raw rows per split with seed 42:

| Split | Median tokens | P95 tokens | Truncated at 128 | Truncated at 192 | Truncated at 256 |
|---|---:|---:|---:|---:|---:|
| Train sample | 49 | 208 | 16.20% | 7.32% | 0.12% |
| Validation sample | 49 | 202 | 15.64% | 6.36% | 0.12% |
| Test sample | 48 | 203 | 16.00% | 6.70% | 0.04% |

The training-sample results support 256 as an efficient limit with high observed coverage. Test lengths are reported descriptively. These are sample estimates; training also records exact coverage for its selected train and model-selection subsets. Dynamic batch padding avoids padding every comment to 256. Truncation can still remove relevant text in long comments, and the sampled coverage does not establish that every important toxic span is retained. No model weights were loaded for this audit.

### Fixed data partitions

The seed is 42. Subsets are sampled **after** deduplication, stratified by the binary label, preserving natural class proportions:

| Partition | Default rows | Purpose |
|---|---:|---|
| Train, from official train | 20,000 | Gradient updates and class weights |
| Selection, from official validation | 3,000 | Epoch selection, early stopping, hyperparameter ranking |
| Threshold selection, from official validation | 3,000 | Prediction threshold only, after model selection |
| Test, from official test | 10,000 | Final comparison after all choices are locked |

The two validation portions are disjoint. The code calls the second portion `calibration`, but it calibrates an **operating threshold**, not probabilities. Every run shares the exact same train, selection, calibration, and test rows. The manifest saves original split row indices and dataset fingerprints. Original split boundaries are never shuffled together. Test statistics are inspected for dataset integrity; test predictions never guide architecture, epoch, hyperparameter, or threshold choices.

### 1. Frozen transfer-learning baseline

- Freeze every encoder parameter and run the encoder in evaluation mode with no gradients.
- Compute mean-pooled embeddings once for train and selection; cache them on disk.
- Train only the same linear classifier head, with fixed AdamW settings: learning rate 1e-3, weight decay 0.01, head dropout 0.1, at most 10 epochs.
- Select the epoch by selection AP with fixed early-stopping patience 1. There is no baseline hyperparameter search.
- Verify the encoder's SHA-256 digest is unchanged and its parameters received no gradients. Save the baseline before tuning starts.

Caching embeddings avoids repeating millions of encoder operations while training the baseline head. Feature extraction time and head fitting time are recorded separately.

### 2. Untuned end-to-end fine-tuning

Unfreeze **every encoder parameter**, starting from the frozen-trained baseline checkpoint. This makes the experiment a direct continuation of transfer learning. The fixed initial configuration uses encoder learning rate 2e-5, weight decay 0.01, and head dropout 0.1. The head learning rate is five times the encoder rate. Fine-tune for at most three epochs and keep the best selection-AP checkpoint. Verify the encoder weights actually changed.

### 3. Hyperparameter tuning

Use seeded **random search without replacement**, selecting four configurations from:

| Hyperparameter | Candidate values |
|---|---|
| Encoder learning rate | 1e-5, 3e-5, 5e-5 |
| Weight decay | 0, 0.01, 0.1 |
| Classifier-head dropout | 0.1, 0.2 |

The untuned fine-tuned model is an incumbent, so the selected configuration may remain unchanged if no sampled trial improves selection AP. Every candidate restarts from the **same frozen baseline weights** and uses the same shuffled training order, maximum epochs, and early-stopping rule. Trials do not continue one another. Epoch selection is part of the search. The search explores head dropout; the encoder's pretrained dropout settings remain fixed.

Four trials limit compute while exploring learning rate and regularization. This is a small assignment search, not proof of global optimality. A one-seed run cannot quantify training-seed variance.

All training uses class-weighted cross-entropy with `weight[c] = N_train / (2 * count_train[c])`, computed only from the sampled training rows. Validation and test remain naturally distributed. Weighted training makes the softmax output a **model score**, not a calibrated estimate of human toxicity probability. A fixed 0.5 score threshold need not be optimal.

Optimization uses float32 for portability, AdamW, 10% linear warmup followed by linear decay, gradient clipping at 1.0, microbatch size 16, and accumulation over two microbatches (effective batch 32 except the final partial batch). Bias and layer-normalization parameters are excluded from weight decay. It automatically selects CUDA, Apple MPS, or CPU. No external training tracker is enabled.

### Final evaluation

Lock the selected checkpoint before evaluating test. For frozen, untuned, and tuned models, choose a prediction threshold maximizing toxic F1 on the separate calibration portion; ties choose the higher threshold. Test is then evaluated at both the common score threshold **0.5** and the separately selected threshold for each model. This distinguishes representation improvements from changes in the operating point.

The report includes the full comparison, per-class metrics, confusion matrices, precision–recall curves, selection histories, and paired stratified bootstrap 95% intervals for AP and toxic-F1 differences relative to the frozen baseline. The same resampled test indices are used for both models, and thresholds remain fixed. These intervals reflect test-sample uncertainty conditional on the fitted models, not training-seed variance or deployment prevalence shift. Fine-tuning or tuning is not assumed to improve test performance.

## Interpretability and real-world text

[`examples/real_world.jsonl`](examples/real_world.jsonl) contains six short, sourced public excerpts: issue replies, a hostile forum remark, a harsh mailing-list response, an apology, and a statement opposing abuse. Each entry includes a source URL, provenance, and an explicitly subjective expected label. Some are excerpts rather than complete messages, so missing context matters. They were selected independently of model outputs and are excluded from training and hyperparameter selection.

[`examples/stress_cases.jsonl`](examples/stress_cases.jsonl) contains separately identified authored examples for identity mentions, negation, reported abuse, and profanity in praise. These are diagnostic checks, not sourced real-world comments or a demographic fairness evaluation.

The explanation command scores every external example using all three models. It checks normalized overlap against the saved experiment subsets; this cannot establish independence from the complete Civil Comments corpus or pretraining data. It does not present an accuracy claim from a handful of curated examples.

LIME explains up to six tuned-model predictions: a true positive, true negative, false positive, false negative (when present), plus two authentic external excerpts. Test cases are selected after final evaluation for diagnosis only, preferring short texts and choosing a confident example within each category. This selection is not representative sampling. LIME masks individual word occurrences with `[MASK]`, preserving order, and fits a local surrogate over 512 perturbations. It saves word contributions, local surrogate R², a second-seed stability check, PNG plots, and HTML explanations. Positive contributions raise the surrogate's toxic score. Attribution describes model behavior around the perturbed text; it does not establish causality or reveal human intent. Low fidelity and unstable rankings should reduce trust in the explanation.

## Use the existing UV environment

Run these commands from this assignment directory. The environment already exists at `../../.venv`; no `uv venv`, `uv init`, or new project environment is needed.

```sh
# Install any missing dependencies into the existing environment.
uv pip install --python ../../.venv/bin/python -r requirements.txt

# Required Hugging Face loader: load_dataset("google/civil_comments").
../../.venv/bin/python -m toxicity.analyze

# Optional tokenizer-only EDA. Downloads tokenizer files, not model weights.
../../.venv/bin/python -m toxicity.token_lengths --source local

# Training and final evaluation: run when ready to spend training compute.
# The default source uses the required google/civil_comments Hub loader.
../../.venv/bin/python -m toxicity.experiment --output artifacts/run

# Real-world predictions and interpretability after training completes.
../../.venv/bin/python -m toxicity.explain --run artifacts/run

# Classify a new comment.
../../.venv/bin/python -m toxicity.predict --run artifacts/run --text "Thanks for explaining this clearly."
```

To reuse the downloaded Parquet files instead of downloading another copy from the Hub, pass `--source local` to `toxicity.analyze` or `toxicity.experiment`. The completed full-split audit used this local path. Hub loading and local Parquet loading use the same downstream preprocessing. A local run records `dataset_source: local` transparently; it does not claim to have invoked the Hub loader.

If the existing environment is elsewhere, replace `../../.venv/bin/python` with its interpreter path. `uv pip install --python ...` explicitly targets that environment; it does not silently create or synchronize another environment. Dependency additions made during this work were `datasets` and `transformers` plus their dependencies. LIME remains a dependency to install before explaining predictions. The parent project's `pyproject.toml` and `uv.lock` were not edited. `requirements.txt` pins Datasets, Transformers, and LIME and bounds other dependencies; exact runtime package versions are saved, but the file is not a complete reproducibility lock.

Edit [`config.json`](config.json) before a run to change the compute budget. For lower memory, use batch size 8 and accumulation 4, keeping effective batch size 32. Reduce sample sizes or trial count for a shorter experiment. Use a fresh `--output` directory for a new run; existing results are not overwritten. Seeds and saved row manifests support repeatability, but exact numerical reproducibility across CUDA, MPS, and CPU is not guaranteed.
